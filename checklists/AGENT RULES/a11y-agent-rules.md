# Правила доступности для ИИ-агентов

Для агентов, реализующих дизайн-систему, дизайн (Figma) и код (React). Платформа: web. Стандарт: **WCAG 2.2 AA**.

ID в скобках ведут в чеклисты: `D-` — [для дизайнера](a11y-design.md), `R-` — [для разработчика](a11y-development.md); общие правила — [a11y-general.md](a11y-general.md).

## Правила

1. **Стандарт:** WCAG 2.2 AA. Решение, ухудшающее доступность, не принимается даже «для скорости»; предложи доступную альтернативу.
2. **Сначала нативный HTML, потом ARIA** (R-01, R-04).
3. **Только токены:** цвет, размер, отступы берутся из токенов; новую пару цветов проверь на контраст (D-05, R-23).
4. **Каждый интерактивный элемент** имеет имя, роль, состояние, клавиатуру и видимый фокус (R-05, R-09, R-11, D-12).
5. **Не выдумывай** alt, label и тексты. Если неизвестны, оставь TODO и укажи в ответе в «Вопросах». Запрещены заглушки вроде `alt="image"`, `aria-label="button"`.
6. **Не удаляй focus outline**, не используй `tabindex > 0`, не блокируй масштабирование (R-10, R-11, R-22).
7. **Конфликт требований** (бренд против контраста, дизайн против семантики): выбери доступный вариант и явно сообщи о конфликте.
8. **Не изобретай виджеты:** модалки, меню, combobox — по APG или из headless-библиотеки (R-04, R-30).
9. **Для icon-only, изображений и полей** делай a11y-пропсы обязательными в TypeScript (`aria-label`, `alt`, `label`).
10. **Тема высокого контраста** поддерживается на уровне токенов; не хардкодь цвета, ломающие её (D-07, R-24).

## Самопроверка перед ответом

- [ ] Нативные элементы; у всех контролов есть имя
- [ ] Клавиатура и фокус по APG; фокус виден
- [ ] Контраст через токены; смысл не только цветом
- [ ] Ошибки и статусы объявляются
- [ ] 200% и 320px, `prefers-reduced-motion`, тема высокого контраста
- [ ] Lint и axe проходят
- [ ] Допущения и вопросы перечислены, ничего не угадано

## Формат ответа

```
Компонент:
Проверено (ID): D-xx, R-xx, ...
Отклонения и допущения:
Вопросы (alt, тексты, конфликты):
```
